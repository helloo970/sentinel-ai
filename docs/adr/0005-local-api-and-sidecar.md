# 5. Local API protection and backend as Tauri sidecar

- Status: accepted
- Date: 2026-10-20

## Context

The backend is an HTTP server on the user's PC. Other local programs and web pages
(via DNS rebinding or CSRF) must not be able to use it.

## Decision

- Bind to `127.0.0.1` only (enforced by config validation).
- Random port and 256-bit token per start, generated by the Tauri shell and passed via
  environment. The frontend gets them through a Tauri command; they are never stored
  in the frontend or logged. In standalone dev mode the backend writes them to
  `session.json` in the user's data directory.
- Pure ASGI guard middleware: `Host` must be `127.0.0.1:<port>` or `localhost:<port>`
  (DNS rebinding), `Origin` must be the app, `Authorization: Bearer <token>` with
  constant-time comparison. CORS only for the app origins. No OpenAPI/docs endpoints.
- Release builds run the backend as a PyInstaller sidecar; the backend exits when the
  parent PID disappears.
- Tray menu and global hotkey send the emergency stop directly from Rust, so it works
  even when the window is hidden.

## Consequences

- Same-user processes could still read the token from the process environment. This is
  accepted: they could equally read the user's files. Admin-level isolation is out of
  scope.
